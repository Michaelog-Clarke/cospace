# Booking API

Bookings are persisted through Prisma using the `Booking` model. The API uses the model's scalar fields:

- `id: number` — generated by the database
- `user_id: number` — the ID of the booking's user
- `desk_id: number` — the ID of the booked desk
- `booking_date: string` — an ISO calendar date (`YYYY-MM-DD`) in requests
- `active: boolean` — defaults to `true` when omitted on create

The repository exposes asynchronous `findAll`, `findPaginated`, `findById`, `create`, `update`, and `delete` operations, along with `count` for pagination metadata. Prisma returns `booking_date` as a `Date`, which Express serializes as an ISO timestamp in responses.

## Booking routes

### `GET /bookings`

Returns a page of bookings and pagination metadata. `page` defaults to `1`, `limit` defaults to `10`, and the maximum page size is `50`.

### `GET /bookings/:id`

Returns the booking with the given positive integer ID, or a 404 response if it does not exist.

### `POST /bookings`

Creates a booking. The request body requires `user_id`, `desk_id`, and a valid `booking_date`; `active` is optional.

```json
{
  "user_id": 12,
  "desk_id": 4,
  "booking_date": "2026-09-22",
  "active": true
}
```

### `PUT /bookings/:id` and `PATCH /bookings/:id`

`PUT` validates the full create shape and replaces the booking's editable fields. `PATCH` accepts any subset of `user_id`, `desk_id`, `booking_date`, and `active`.

### `DELETE /bookings/:id`

Deletes the booking and returns `204 No Content`. Missing IDs return 404.
